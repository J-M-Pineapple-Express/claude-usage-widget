How Claude Usage works

Everything the widget shows, where each number comes from, and how Auto Continue decides when to act. Nothing leaves your computer except the widget's own requests to claude.ai, signed in as you.

Context

How full the Claude Code conversation you're working in is, so you see auto-compaction coming.

  • Where it comes from: the session's transcript file in ~/.claude/projects/. The widget reads the token count Claude Code recorded for the last reply, every 15 seconds. It's a local file read, not a claude.ai request.
  • The bar measures against about 80% of the window (800K of 1M), which is roughly where Claude Code compacts. Green under 40%, yellow under 70%, red above.
  • Click the detail line to switch the window size (200K / 500K / 1M) if your model's window differs.
  • jsonl is the transcript's size on disk. Green under 12 MB, yellow under 15 MB, red above. Big transcripts are slow to resume.
  • Which session? The one that was active most recently, unless you've pinned one (see Sessions).

Sessions

Everything Claude is doing for you right now, in one list.

  • In widget: the session the Context bar is measuring. Hover it for its recap; click it to open the recap in a window.
  • Running sessions (terminals, VS Code): read from Claude Code's own records in ~/.claude/sessions/. Green dot = working, grey = idle. Click one to expand it; show in widget pins it to the Context bar, recap ↗ opens its recap.
  • Claude Desktop: Code and Cowork sessions from the desktop app's records, active in the last day.
  • Chats: your claude.ai chats and Claude Desktop's chats, active in the last day, read from claude.ai. "needs you" means Claude is waiting on you. Click to open it.
  • Bots & scripts: things that drive Claude Code headless with claude -p --resume (like a Discord bot). They only show busy while replying.
  • scheduled tasks ↗: your scheduled Cowork tasks, with Desktop's blue dot when a run is unread or waiting on you.
  • open sessions window ↗: the same information with more room.

Limits

  • 5-hour: how much of your current 5-hour usage window you've used, and when it resets.
  • Weekly: the same for your weekly limit.
  • Where it comes from: the same data as claude.ai's Settings → Usage page, requested once a minute (↻ refreshes now). The widget signs in with the claude.ai login you gave it the first time; there's no API key.

Extra usage

  • Spend: extra usage (usage credits past your plan's limits) this month, or "off" if it isn't turned on.
  • Balance: prepaid credits you have left.
  • Resets: one-off resets Anthropic sometimes gives out that refill your 5-hour and weekly limits when you choose to use one. Shows how many you have and when they expire. Click it to open claude.ai, where you use a reset; the widget never uses one for you.

Auto Continue

When Claude Code stops because you hit a usage limit, Auto Continue waits for the limit to reset, then types a message into that same window telling Claude to pick up where it left off. You don't have to be there.

The pieces, and what watches what

1
Claude Code, via a hook
Turning the switch on adds a small hook to ~/.claude/settings.json (a StopFailure hook for rate limits). Claude Code runs it only when a reply stops on a usage limit. It doesn't run otherwise and costs nothing.
2
The hook
Writes down which session stalled and which window it's in (the terminal, VS Code or app window), plus any agents the limit interrupted, into a queue file: ~/.claude/auto-continue-queue.json. Then it exits.
3
The widget
Every minute, when it checks your usage, it also looks at that queue. It waits until both the 5-hour and weekly bars are under 100%, because if either is still full, Claude would stop again right away.
4
The widget, when limits reset
Brings that session's window to the front, pastes "I had hit my token limit previously, please continue where we left off." and presses Enter. That session's entry leaves the queue, and the send is logged under activity.

What it needs to work

  • The widget has to be running. Claude Code only records the stall; the widget is what watches the clock and sends the message. If the widget is closed when limits reset, it sends as soon as you open it.
  • The window has to still be open. It types into that exact window; if you closed it, there's nothing to type into.
  • The computer has to be unlocked. Windows won't let an app type while the lock screen or screensaver is up. The widget keeps retrying every minute (up to 30 tries) and sends once you're back.
  • On a Mac, the widget needs Accessibility permission (System Settings → Privacy & Security → Accessibility) to type into another app. It asks when you turn Auto Continue on.

Resume agents

Off (the default): if subagents were interrupted, the message lists them and Claude waits for you to decide. On: the message also tells Claude to restart them. Off is safer, since restarting a batch of agents can spend a fresh window before you're back.

activity

Click activity next to the switch to see what's waiting in the queue, the exact message each session will get, when the widget last checked, and what it has sent before.

Claude Code's own setting: newer Claude Code versions can also continue by themselves when a limit resets (/config → "Continue automatically at usage limit"). That works inside Claude Code, without the widget, but only for that session. If you turn both on, a session may get told to continue twice. Pick one.

What it does not do

  • It doesn't watch your screen or read your conversations. The only thing it knows about a session is what the hook wrote down when it stalled.
  • It doesn't send anything to Anthropic beyond the usage check the widget already makes.
  • Turning the switch off removes the hook and clears the queue. Your settings file is backed up first (settings.json.auto-continue-backup).
